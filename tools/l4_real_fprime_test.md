# L4 procedure: real F´ binary end-to-end file transfer test

The L3 test (`tools/l3_fake_spacecraft.py`) proves the YAMCS service
correctly handles `Fw::FilePacket` traffic generated by *our* Python
codec. L4 is the same test using the real F´ binary as the spacecraft.
If L3 passes and L4 passes, the entire pipeline is verified end-to-end:

```
YAMCS REST POST  ->  TC frame on UDP 50001
                                  ↓
           Svc::CmdDispatcher → Svc::FileDownlink (in F´ binary)
                                  ↓
                  Fw::FilePacket → CCSDS frame on UDP 50000
                                  ↓
        UDP_TM_IN → tm_realtime → FprimeFilePacketService
                                  ↓
                            fprimeFilesIn bucket
                                  ↓
                  GET /api/buckets/.../objects/<name>
                                  ↓
                       sha256 == original file
```

## First-run procedure (from a clean start)

Prerequisites: `default-jdk maven`, `build-essential`, `python3.11-venv`
all installed. Submodules initialized. F´ deployment built. venv
populated. The patched `fprime-xtce` is applied (see
`dict-additions/fprime_xtce_patch/README.md`).

```sh
# 1. Regenerate the vendored XTCE with the patched generator
source fprime-venv/bin/activate
fprime-to-xtce -o FprimeYamcsReference/yamcs/src/main/yamcs/mdb/fprime.xtce.xml \
  build-artifacts/Linux/FprimeYamcsReference_YamcsDeployment/dict/YamcsDeploymentTopologyDictionary.json

# 2. Launch YAMCS via mvn (NOT fprime-yamcs — its hardcoded pom path
#    bypasses our vendored Java code). Source the venv so the
#    fprime-yamcs-events ProcessRunner can find its binary.
( cd FprimeYamcsReference/yamcs && mvn yamcs:run -Dyamcs.directory=/tmp/yamcs-data ) > /tmp/yamcs.log 2>&1 &

# 3. Wait for YAMCS to boot (~25 s)
sleep 25
curl -s -o /dev/null -w "yamcs http: %{http_code}\n" http://localhost:8090/

# 4. Launch the F´ binary in parallel. -p 50000 means TM out to :50000
#    and TC in bound to :50001 (port+1). Both match YAMCS config.
build-artifacts/Linux/FprimeYamcsReference_YamcsDeployment/bin/FprimeYamcsReference_YamcsDeployment \
  -a 127.0.0.1 -p 50000 > /tmp/fprime-bin.log 2>&1 &

# 5. Wait a couple seconds, then verify YAMCS is receiving real F´ TM
sleep 3
curl -s "http://localhost:8090/api/links/fprime-project" | grep -A2 dataInCount
# Expect: dataInCount > 0, status=OK, "Valid frames" > 0, "Invalid frames" = 0

# 6. Issue the FileDownlink.SendFile command via REST. Source path is
#    relative to F´'s cwd (the repo root). Destination is the bucket key.
curl -s -X POST \
  "http://localhost:8090/api/processors/fprime-project/realtime/commands/FprimeYamcsReference%7CYamcsDeployment/FileHandling%7CfileDownlink%7CSendFile" \
  -H "Content-Type: application/json" \
  -d '{"args":{
        "FileHandling|fileDownlink|SendFile|sourceFileName":"README.md",
        "FileHandling|fileDownlink|SendFile|destFileName":"readme_from_fprime.md"
      }}' > /dev/null

# 7. Watch YAMCS log for the service's two log lines:
sleep 2
grep FprimeFilePacketService /tmp/yamcs.log | tail -3
# Expect:
#   File transfer START: seq=0 size=1184 src=README.md dst=readme_from_fprime.md
#   File transfer COMPLETE: readme_from_fprime.md (1184 bytes) -> bucket fprimeFilesIn

# 8. Download the file from the bucket and verify it matches the original
curl -s "http://localhost:8090/api/buckets/_global/fprimeFilesIn/objects/readme_from_fprime.md" \
  -o /tmp/downloaded_readme.md
diff -q /tmp/downloaded_readme.md README.md && echo "L4 PASSED: bit-for-bit match"
```
